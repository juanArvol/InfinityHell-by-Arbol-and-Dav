  HRFC — INSTRUCCIONES DE EJECUCIÓN DEL STRESS TEST
═══════════════════════════════════════════════════════════════════════════

ESTADO: El profiling está ACTIVADO automáticamente en GameWorldBootstrap.

PASOS PARA EJECUTAR EL STRESS TEST:

1. COMPILAR EL PROYECTO
   ──────────────────────
   Asegurarse de que todos los cambios están compilados:
   - Game/Engine/Profiling/*.java
   - Game/Engine/Systems/CollisionsSystem.java
   - Game/World/Core/WorldManager.java
   - Main/Bootstrap/GameWorldBootstrap.java
   - Main/Debug/ProfilingCommand.java

2. EJECUTAR EL JUEGO
   ──────────────────
   Lanzar el juego normalmente.
   Al iniciar, verás en consola:
   
   ═══════════════════════════════════════════════════════════════
     HRFC PROFILING ACTIVO — STRESS TEST MODE
   ═══════════════════════════════════════════════════════════════
   
   INSTRUCCIONES:
   1. Equipar WeaponPistola (360 bullets/shot, cooldown=0)
   2. Disparar CONTINUAMENTE durante 60-90 segundos
   ...

3. EQUIPAR WEAPONPISTOLA
   ──────────────────────
   En el juego:
   - Abrir inventario
   - Seleccionar WeaponPistola
   - Confirmar que tiene: 360 bullets/shot, cooldown=0

4. DISPARAR CONTINUAMENTE
   ───────────────────────
   - Mantener el botón de disparo presionado (o click continuo)
   - Duración: 60-90 segundos
   - Observar el comportamiento:
     
     Segundos 0-10:   60 FPS, ~0-800 proyectiles
     Segundos 10-20:  55-45 FPS, ~800-1200 proyectiles
     Segundos 20-30:  40-25 FPS, ~1200-1800 proyectiles
     Segundos 30-45:  20-10 FPS, ~1800-2500 proyectiles
     Segundos 45-60:  5-3 FPS, ~2500-3000+ proyectiles
     Segundos 60+:    Proyectiles comienzan a morir
     Segundos 70-90:  FPS recupera progresivamente

5. REGISTRAR OBSERVACIONES VISUALES
   ─────────────────────────────────
   Mientras juegas, observar mentalmente:
   - ¿Cuándo comienza la degradación notable?
   - ¿El rendering se ve lento (sprites jerky)?
   - ¿La simulación se ve lenta (movimiento pausado)?
   - ¿Las colisiones se registran correctamente?

6. DETENER Y CERRAR
   ──────────────────
   - Dejar de disparar
   - Permitir que todos los proyectiles mueran
   - Observar recuperación de FPS
   - Cerrar el juego normalmente

7. RESULTADO AUTOMÁTICO
   ────────────────────
   Al cerrar, verás en consola:
   
   ═══════════════════════════════════════════════════════════════
     HRFC — BOTTLENECK DIAGNOSIS REPORT
   ═══════════════════════════════════════════════════════════════
   
   Profiling Duration:  XX.XX seconds
   Frames Collected:    XXXX frames
   ...
   PRIMARY BOTTLENECK:  ...
   ...
   
   [ProfileCollector] Exported XXXX frames to: profiling_results.csv

8. ANÁLISIS DETALLADO
   ───────────────────
   Si tienes Python instalado:
   
   python analyze_profiling_results.py profiling_results.csv
   
   Esto generará:
   - Tabla por rangos de proyectiles
   - Punto exacto de degradación
   - Worst case
   - Distribución de subsistemas
   - Cuello de botella detectado
   - Análisis de escalamiento

9. SI PYTHON NO ESTÁ DISPONIBLE
   ─────────────────────────────
   Abrir profiling_results.csv con Excel:
   - Crear tabla dinámica
   - Agrupar por activeProjectiles (rangos de 500)
   - Calcular promedios de fps, frameTimeMs, simulationMs, etc.
   - Graficar activeProjectiles vs frameTimeMs

10. DATOS ESPERADOS
    ───────────────
    El CSV contendrá aproximadamente:
    - 3000-5000 frames (últimos 50-83 segundos de juego)
    - Columnas: frame, activeProjectiles, fps, frameTimeMs, simulationMs, 
                collisionMs, renderingMs, behaviorMs, movementMs, etc.
    
    Buscar específicamente:
    - ¿Qué subsistema domina cuando activeProjectiles > 2000?
    - ¿Cómo crece cada subsistema: lineal o superlineal?
    - ¿Rendering, Collision o Simulation es el PRIMARY BOTTLENECK?

11. TROUBLESHOOTING
    ───────────────
    Si no aparece el mensaje de profiling al iniciar:
    → Verificar que GameWorldBootstrap está compilado
    → Verificar que ProfilingCommand.startStressTest() no está comentado
    
    Si el juego crashea:
    → El profiling con 5000 frames usa ~5-10 MB RAM
    → Si maxFrames es muy alto, reducirlo en ProfilingConfig
    
    Si profiling_results.csv no se genera:
    → Verificar permisos de escritura en el directorio del juego
    → Verificar que ProfilingConfig.autoExportOnShutdown = true

12. SIGUIENTE PASO
    ──────────────
    Una vez obtenidos los resultados:
    
    1. Revisar el resumen en consola
    2. Analizar profiling_results.csv
    3. Determinar PRIMARY BOTTLENECK con evidencia
    4. Identificar hotspot específico dentro del subsistema
    5. Reportar hallazgos sin implementar optimizaciones todavía
